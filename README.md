# Asira Clear Bot v0.3.15

Minecraft統合版のBotをDiscordとWebから操作する、既存MCBOTサービス用の更新版です。最大20アカウントを登録できます。

[更新ガイド](UPDATE-v0.3.15-JA.md) · [初回設定](START-HERE-JA.md) · [Web操作](WEB-GUIDE-JA.md) · [コマンド](COMMANDS-JA.md) · [検証記録](VALIDATION-v0.3.15.md)

## 今回の変更

- IGNのWorld移動を、正確なコマンド `/world cpe` に修正しました。古い既定値 `coe` も移行します。
- Minecraftのゲーマータグとグリーター対象IDはWebで登録・保存できます。VariablesへのID記入は不要です。既存の保存済みアカウントは引き継ぎ、新規環境は空の一覧から始めます。
- Webログインを更新・タブを閉じた後も保持します。同じDiscordアカウントで別のタブや端末にログインしても、前のログインを取り消しません。
- 更新中の一時的な通信エラーでは再接続を待ちます。Webを閉じてもMinecraftは切断しません。バックエンド再起動後は、保存認証と接続希望を確認してMinecraftへ再接続します。
- 一括ON/OFFを各機能の「⋯」へ、アカウント追加をダイアログへ移動しました。グリーターなどの詳細設定も折り畳み、画面を整理しました。

## 更新

ZIPを解凍し、`AsiraClearBot` フォルダの中身を既存GitHubへ上書きします。`src`・`web`・`vendor`・`scripts`・両packageファイル・Dockerfileを含めてください。Railwayのデプロイ成功後、WebをCtrl+F5で再読み込みし、右上の `v0.3.15` を確認します。既存のVariables・保存データは維持してください。

この版を入れた後、一度「接続」で接続してください。以後は接続希望も保存し、再起動時に保存認証で再接続します。「切断」・認証のキャンセル・AutoLogによる切断は自動再接続の対象から外します。AutoLogの既存の安全確認による再入場は引き続き使用できます。

## 保存とログイン

RailwayではMCBOTサービスにVolumeを接続し、Mount Pathを `/data` にしてください。`DATA_DIR=/data` を設定するか、VolumeのMount Path自動検出を利用します。DATA_DIRの文字を設定するだけではVolumeは作成されません。再デプロイをまたいで認証・Webログイン・設定を残すには、この保存先が必要です。

WebのログインCookieは通常30日間で、利用中は更新します。同じ公開ドメイン・同じブラウザの通常モードで使ってください。Cookie削除、シークレットモード終了、ドメイン変更、期限切れ、権限の取り消し、明示的なログアウトでは再ログインが必要です。Microsoft側で認証が失効した場合も再認証が必要です。

コード更新によるプロセス再起動中はMinecraftとの通信自体はいったん切れます。保存したアカウントで再接続する機能であり、サーバーが接続を許可することや作業の自動再開を保証するものではありません。認証情報を含む `data` や `.env` をGitHubへ公開しないでください。

## ローカル実行

Node.js 24を使います。`.env.example` を `.env` にコピーし、Discord Tokenなどを設定します。ローカルの保存先は `DATA_DIR=./data` に変更してください。`npm ci` → `npm start` で起動します。Webからアカウントを追加し、Bot用のMicrosoftアカウントで認証します。
